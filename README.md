# SoundMess

Музыкальный веб-сервис на Django с каталогом треков и релизов, непрерывным воспроизведением и личной медиатекой. Слушатели открывают новую музыку и поддерживают артистов, артисты публикуют свои работы, а модераторы управляют контентом через собственную панель.

Проект создан в учебных целях. Пополнение кошелька и поддержка артистов работают с виртуальными средствами, без реальных платежей.

## Возможности

- **Сквозной плеер.** Воспроизведение продолжается при переходах между страницами. Доступны очередь, перемотка, регулировка громкости и повтор трека.
- **Каталог и поиск.** Фильтры по жанру, настроению, темпу, году, длительности, типу релиза, наличию текста и explicit-контенту. Сортировка по дате, прослушиваниям и лайкам.
- **Личная медиатека.** Любимые треки, приватные плейлисты, сохранённые релизы и история прослушиваний.
- **Общение и подписки.** Лайки, комментарии с таймкодами, ответы и лента публикаций любимых артистов. Действия обновляют интерфейс без перезагрузки страницы.
- **Кабинет артиста.** Загрузка аудио, обложек и текстов, создание синглов, альбомов, EP и микстейпов. Черновики, отправка на проверку, топ-5 треков и статистика за 7 или 30 дней.
- **Модерация.** Заявки артистов, проверка треков и релизов, управление комментариями, журнал решений. Администраторы также управляют пользователями и виртуальными балансами.
- **Кошелёк.** Пополнение, поддержка артистов и история операций. Переводы выполняются атомарно и защищены от повторной отправки.
- **Адаптивный интерфейс.** Тёмная тема с оранжевым акцентом и раскладкой для мобильных устройств.

Прослушивание учитывается после 30 секунд фактического воспроизведения. Паузы и перемотки не увеличивают счётчик.

### Роли и доступ

| Роль | Доступ |
| --- | --- |
| Гость | Публичный каталог, страницы артистов и релизов, чтение комментариев, прослушивание |
| Слушатель | Медиатека, лайки, комментарии, подписки, кошелёк и поддержка артистов |
| Артист | Возможности слушателя, загрузка музыки, создание релизов и аналитика после одобрения заявки |
| Модератор | Проверка заявок и публикаций, модерация комментариев |
| Администратор | Модерация, управление пользователями и балансами |

Треки и публичные релизы проходят предварительную модерацию. Изменение опубликованного материала требует повторной проверки. Приватные плейлисты доступны только владельцу.

## Стек

| Компонент | Технологии |
| --- | --- |
| Сервер | Python 3.12–3.14, Django 6.0.3 |
| База данных | SQLite |
| Интерфейс | Django Templates, CSS, JavaScript ES Modules, Fetch API |
| Проверка аудио и длительности | Mutagen 1.48.1 |
| Работа с изображениями | Pillow 12.1.1 |

Frontend работает без сборки и установки npm-пакетов. Серверные обработчики синхронные; переходы между страницами и интерактивные действия выполняются через асинхронные запросы в браузере.

## Быстрый старт

Понадобятся Git и Python 3.12, 3.13 или 3.14.

Склонируйте репозиторий и перейдите в каталог приложения:

```bash
git clone https://github.com/4Zepar/SoundMess.git
cd SoundMess/my_app
```

### Windows / PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

Активация виртуального окружения и изменение политики выполнения PowerShell не требуются.

### Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver
```

Откройте [localhost:8000](http://127.0.0.1:8000/). При первом запуске каталог пуст: загрузите собственные треки через кабинет артиста или создайте тестовые данные командой ниже.

Все последующие команды Python выполняются из `my_app/`. В Linux и macOS вместо `.\.venv\Scripts\python.exe` используйте `.venv/bin/python`.

### Административный аккаунт

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

После входа доступны:

- [Собственная панель управления](http://127.0.0.1:8000/moderation/) — заявки, публикации, комментарии и пользователи.
- [Django Admin](http://127.0.0.1:8000/admin/) — техническое управление данными.

Суперпользователь имеет полный доступ к обеим панелям. Для остальных сотрудников права собственной панели задаются группами «Модераторы» и «Администраторы»; одного флага `is_staff` недостаточно.

## Тестовый каталог и аккаунты

Для знакомства с функциями сервиса выполните после миграций:

```powershell
.\.venv\Scripts\python.exe manage.py seed_demo --with-sample-audio
```

Команда запросит общий пароль для новых аккаунтов — не менее 10 символов. Она создаст аккаунты, шесть тестовых треков, два EP, плейлист, комментарий с таймкодом, примеры статистики и начальный баланс слушателя.

| Логин | Роль |
| --- | --- |
| `demo_listener` | Слушатель |
| `demo_pulse`, `demo_echo` | Одобренные артисты |
| `demo_moderator` | Модератор |
| `demo_admin` | Администратор |

Тестовое аудио — синтетические сигналы по 40 секунд, которые генерируются локально. Они подходят для проверки плеера и счётчика прослушиваний. Готовых музыкальных записей в репозитории нет.

Без флага `--with-sample-audio` команда создаёт аккаунты, подписку и начальный баланс без каталога. Повторный запуск не сбрасывает пароли и права существующих аккаунтов. Для автоматического запуска пароль можно передать через переменную окружения `SOUNDMESS_DEMO_PASSWORD`.

## Устройство проекта

```text
SoundMess/
├── my_app/
│   ├── manage.py
│   ├── requirements.txt
│   ├── my_app/                 # Настройки Django, маршруты, WSGI и ASGI
│   ├── pc_store/
│   │   ├── models.py           # Модели и связи
│   │   ├── forms.py            # Формы и валидация
│   │   ├── selectors.py        # Выборки каталога и агрегаты
│   │   ├── services/           # Публикация, модерация и платежи
│   │   ├── views/              # Страницы и JSON-обработчики по разделам
│   │   ├── management/commands/
│   │   ├── migrations/
│   │   ├── static/pc_store/    # Стили и JavaScript-модули
│   │   └── tests/              # Серверные тесты
│   └── templates/              # Общая оболочка, страницы и компоненты
├── tests/frontend/             # Тесты логики JavaScript
├── package.json                # Команда запуска frontend-тестов
└── ARCHITECTURE.md              # Подробная техническая документация
```

Приложение построено как Django-монолит. Правила публикации и переводы вынесены в сервисы, выборки — в селекторы, обработчики — в модули по функциональным разделам. Постоянный плеер остаётся в общей оболочке страницы, а навигация заменяет её содержимое.

Описание моделей, маршрутов, форматов API, прав доступа, плеера и ограничений: **[архитектура проекта](ARCHITECTURE.md)**.

## Настройки и данные

Настройки читаются из переменных окружения процесса:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DJANGO_DEBUG` | `True` | Режим разработки |
| `DJANGO_SECRET_KEY` | Ключ для локальной разработки | Подпись сессий и служебных токенов |
| `DJANGO_ALLOWED_HOSTS` | `127.0.0.1,localhost` | Допустимые хосты |
| `DJANGO_DB_PATH` | `my_app/db.sqlite3` | Путь к SQLite |
| `DJANGO_MEDIA_ROOT` | `my_app/media/` | Каталог загруженных файлов |

Пример находится в [my_app/.env.example](my_app/.env.example). Файл `.env` автоматически не загружается.

База, загруженное аудио, изображения, виртуальное окружение и локальные секреты исключены из Git. Для переноса существующего каталога нужно отдельно перенести базу и `media/`. Проверка файлов, резервное копирование и восстановление описаны в [ARCHITECTURE.md](ARCHITECTURE.md#section-26).

Настройки по умолчанию рассчитаны на локальный запуск. Для публичного размещения нужны отдельная конфигурация с `DEBUG=False`, собственный секретный ключ, HTTPS, сервер WSGI/ASGI и настроенная раздача статики и аудио.

## Проверки

Из каталога `my_app/`:

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test pc_store
```

Тесты используют отдельную базу и временный каталог файлов.

Для проверки JavaScript нужен Node.js 20+. Из корня репозитория:

```bash
node --test tests/frontend/*.test.js
```

Также доступна команда `npm test` (`npm.cmd test` в PowerShell). Установка npm-зависимостей не требуется.
