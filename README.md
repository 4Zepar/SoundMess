# SoundMess

Учебный музыкальный сервис на Django: публичный каталог, сквозной плеер, медиатека, кабинет артиста и собственная панель модерации. Тёмный интерфейс с оранжевым акцентом адаптирован для телефона.

## Запуск в Windows / VS Code

Нужен Python 3.12–3.14. Команды выполняются из папки репозитория.

```powershell
Set-Location my_app
py -3.14 -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.txt
& '.\.venv\Scripts\python.exe' manage.py migrate
& '.\.venv\Scripts\python.exe' manage.py runserver
```

Откройте http://127.0.0.1:8000/. Если окружение уже создано и зависимости установлены, достаточно последних двух команд. Активация виртуального окружения и изменение ExecutionPolicy не требуются.

Для своего административного аккаунта:

```powershell
& '.\.venv\Scripts\python.exe' manage.py createsuperuser
```

Основная панель управления находится по адресу /moderation/. Стандартная панель Django по адресу /admin/ сохранена для технического обслуживания.

## Демонстрационные данные

На новой базе можно создать пять демо-аккаунтов, начальный виртуальный баланс и небольшой каталог:

```powershell
& '.\.venv\Scripts\python.exe' manage.py seed_demo --with-sample-audio
```

Команда запросит общий пароль для новых аккаунтов — минимум 10 символов. Для автоматического запуска поддерживается переменная окружения SOUNDMESS_DEMO_PASSWORD. Повторный запуск не меняет пароли или права уже существующих аккаунтов.

| Аккаунт | Назначение |
| --- | --- |
| demo_listener | Слушатель: любимое, плейлист, подписки, баланс |
| demo_pulse, demo_echo | Одобренные артисты: треки, EP и аналитика |
| demo_moderator | Заявки, материалы и комментарии |
| demo_admin | Модерация, аккаунты и корректировка балансов |

Аудио с пометкой «[Демо]» — оригинальные тихие синтетические сигналы длительностью 40 секунд для проверки плеера и счётчика. Это тестовые записи, а не музыкальные произведения. Без флага --with-sample-audio команда создаёт только аккаунты, подписку и начальный баланс.

В рабочую базу демонстрационные данные автоматически не добавляются.

## Как показать основные функции

1. Без входа откройте каталог и включите трек. Перейдите к артисту и релизам: воспроизведение продолжается. Через 30 секунд фактического воспроизведения регистрируется прослушивание; пауза и перемотка не засчитываются.
2. Войдите слушателем. Нажмите сердечко: число лайков обновится без перезагрузки, трек появится в «Любимом». Добавьте его в плейлист.
3. На странице трека оставьте комментарий во время воспроизведения. Он получит текущий таймкод; нажатие по времени перематывает плеер. Доступны ответы до трёх уровней.
4. Подпишитесь на артиста и откройте «Мои подписки». Здесь показаны опубликованные релизы и отдельные синглы выбранных артистов.
5. В «Демо-кошельке» пополните баланс и подтвердите сумму. На странице другого артиста выполните поддержку. В истории появятся списание и зачисление; повторная отправка подтверждения не дублирует перевод.
6. Подайте заявку артиста из обычного аккаунта. Модератор одобряет её в /moderation/applications/.
7. Одобренный артист загружает аудио и обложку, заполняет метаданные и текст. Доступны черновик и отправка на проверку. Только одобренные материалы попадают в публичный каталог.
8. Соберите релиз из собственных одобренных треков и отправьте его на отдельную проверку. Изменение опубликованного материала требует повторной модерации.
9. В кабинете артиста сравните 7 и 30 дней, посмотрите топ-5 треков. В панели модерации проверьте скрытие комментариев, журнал решений и раздел управления пользователями.

Все платежи используют виртуальные демо USD. Банковские реквизиты и реальное списание денег отсутствуют.

## Доступ и публикация

Гости свободно смотрят публичные страницы и слушают музыку. Лайки, комментарии, подписки, личные плейлисты и платежи требуют входа.

Права модератора задаются группой «Модераторы», администратора — группой «Администраторы». Суперпользователь имеет полный доступ. Сам флаг is_staff не предоставляет права в собственной панели. Модератор не может изменять пользователей или баланс. Собственные заявки и материалы проверяет другой модератор.

Черновики, ожидающие проверки, отклонённые и скрытые материалы видны владельцу и модераторам. Блокировка артиста скрывает его публичные материалы. Прямое обращение к аудио проходит ту же проверку доступа; раздача каталога music/ через /media/ отключена.

Приватные плейлисты и публичные авторские релизы разделены. «Любимое» хранится в связи Track.likes, сохранённые релизы — в Album.saved_by.

## База, файлы и резервные копии

SQLite, загруженные файлы media/, окружение .venv/ и локальные секреты исключены из Git. Они остаются на диске, но не передаются при клонировании. Для переноса существующих данных копируйте базу и media/ отдельно.

Перед важными изменениями создайте согласованную копию SQLite:

```powershell
& '.\.venv\Scripts\python.exe' manage.py backup_db ..\..\backups
```

Копия проверяется командой SQLite integrity_check. Изображения и аудио нужно резервировать отдельно вместе с media/. Для восстановления остановите сервер и подмените db.sqlite3 выбранной копией, предварительно сохранив текущий файл.

Проверка файлов и обновление длительности старых записей:

```powershell
& '.\.venv\Scripts\python.exe' manage.py audit_media
& '.\.venv\Scripts\python.exe' manage.py audit_media --update-duration
```

Первая команда только читает данные. Вторая сохраняет длительности, прочитанные из существующих аудиофайлов. Команды не удаляют записи и не подбирают замену отсутствующим файлам.

## Проверки

Из my_app/:

```powershell
& '.\.venv\Scripts\python.exe' manage.py check
& '.\.venv\Scripts\python.exe' manage.py makemigrations --check --dry-run
& '.\.venv\Scripts\python.exe' manage.py test pc_store
```

Из корня репозитория, при установленном Node.js 20+:

```powershell
node --test tests/frontend/*.test.js
```

Frontend не требует npm install или сборки. На Windows также можно выполнить npm.cmd test. Серверные тесты используют отдельную тестовую базу и временную папку файлов.

## Настройки окружения

Настройки читаются из переменных процесса; .env автоматически не загружается. Пример находится в my_app/.env.example.

| Переменная | Значение по умолчанию |
| --- | --- |
| DJANGO_DEBUG | True, локальный запуск |
| DJANGO_SECRET_KEY | Локальный ключ разработки |
| DJANGO_ALLOWED_HOSTS | 127.0.0.1,localhost |
| DJANGO_DB_PATH | my_app/db.sqlite3 |
| DJANGO_MEDIA_ROOT | my_app/media/ |

Для отдельного размещения нужны собственный секретный ключ, DEBUG=False, допустимые домены, HTTPS, WSGI/ASGI-сервер и настроенная раздача статики/защищённого аудио. Локальный runserver предназначен для разработки и учебной демонстрации.
